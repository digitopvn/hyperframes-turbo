# Negative results and limits of the fault-injection suite

`<path>.{json,md}` are generated by `benchmarks/src/fidelity/inject-faults.ts`
and keep every row, misses included. This file records what those tables do
not explain on their own. Every number here comes from a committed file named
next to it.

## producer-default.win32 (current run)

Source renders: `benchmarks/results/2026-10-27-1c4a1c1-faults` and
`benchmarks/results/2026-10-27-1c4a1c1-faults-b` (producer-default, 1 cold +
2 warm, `--keep-output`). Faults are injected into warm run 2 and compared with
warm run 1.

- **The first render aborted fail-closed.** After 6 of 13 fixtures the host
  guard stopped the run on `commit charge 116.1 GiB > 90% of limit 127.8 GiB`
  (`2026-10-27-1c4a1c1-faults/run-manifest.json` -> `abort`). The commit charge
  came from other workloads on this shared host; no report was written for that
  run. The remaining 7 fixtures were rendered separately into `-faults-b`, with
  the same command and fixture subset flag. `inject-faults.ts` accepts both
  dirs and records which dir each fixture came from (`fixtureResults` in the
  JSON).
- **Result:** 193 rows, 22 distinct fault kinds caught, 1 miss, 7
  near-threshold rows not caught where not required (informational), 0 errors
  (`producer-default.win32.json`).
- **The miss is a false positive on the unmodified control, not a missed
  fault.** motion-blur run 2 vs run 1, both unmodified reference renders,
  FAILs with `PIXEL_BELOW_THRESHOLD`: frame 89 has max|diff| 54 against a
  calibrated limit of 53; every other sampled frame is within limits
  (`2026-10-27-1c4a1c1-faults-b/fidelity/motion-blur-run2-vs-run1.json`). The
  5-run calibration did not observe the full reference spread of this
  non-deterministic fixture. The limit is **not** loosened by hand; the fix is
  a recalibration with more runs, which this change does not do. Until then
  the gate fails closed on motion-blur slightly more often than the reference
  itself varies.
- **Near-threshold A/V offsets:** 22, 25 and 30 ms were caught on both audio
  fixtures (audio-mix, mixed-complex) with A/V drift measured at exactly 22.000,
  25.000 and 30.000 ms against a 21.33 ms limit.
- **Near-threshold pixel faults on non-deterministic fixtures** are
  informational. gsap-static-holds passed both +/-2 luma faults (the change lies
  within its calibrated reference noise). fps-ntsc-30000-1001, typography-svg
  and motion-blur (unsampled) FAILed with `FRAME_CONTENT_UNIDENTIFIED` from the
  temporal check instead of the pixel reason, so they are not counted as
  caught by the expected check.
- **HEVC 10-bit and VP9 alpha frame faults** are now injected: on
  hdr-regression, hdr-hlg-regression and webm-transparency every frame fault,
  including the subtle ones, was caught.

## Not injectable (by design)

- Wrong-resolution and bitrate-drop faults re-encode with x264 and stay
  H.264-only; on HEVC and VP9 outputs they are not applicable rather than
  passed.
- Frame faults are not injected into PNG sequences (no lossless re-encoder is
  needed or used there); the PNG tier is covered by `gate.test.ts`.
- No cross-reference (candidate tolerance) threshold file exists yet: there is
  only one accepted reference configuration (`producer-default`), see
  `docs/fidelity-protocol.md`, *Candidate tolerances*.
